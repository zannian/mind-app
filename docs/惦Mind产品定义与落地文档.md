## 一、产品概述

### 1.1 产品名称

- **中文名**：惦
- **英文名**：Mind
- **Slogan**：你在惦谁 / Mind who matters

### 1.2 产品定位

一款专为情侣/夫妻设计的轻量关怀工具。把"喝水了吗""起来动动""记得吃药"这些琐碎的关心，变成一次点击就能送达的即时提醒。不聊天，不刷屏，只做一件事：**让在乎被看见、被回应。**

### 1.3 产品不是什么

1. 不是聊天 App：不提供自由长聊天、常驻输入框、已读漫游
2. 不是待办清单：只管理当天来自对方的即时关怀，跨天只做记录
3. 不是自动健康计划：MVP 不做周期提醒、智能推荐、步数接入
4. 不是医疗工具：不声称治疗膀胱炎、肾病、结石或脱水

### 1.4 适用场景

- 对方总忘记喝水，需要被提醒
- 想提醒对方起身活动，但对方总说"等一下"然后忘了
- 想让对方知道你在惦记她，但不想发微信那么正式
- 想记录对方的健康习惯，又不想变成"监工"

## 二、核心价值主张

### 2.1 三个关键词

| 关键词 | 体现 |

### 3.1 Logo 概念

从"惦"的竖心旁"忄"演变为一棵树，树上挂着两颗心。

| "忄"笔画 | Logo 语义 |

| 左点 | 一颗心 |
| 右点 | 一颗心 |

- 同一棵树 → 两个人被同一段关系连接

- 已回应卡片：折角出现时轻微展开（0.2s）
- 不做长时间动画或持续占用 CPU

## 五、Tab 1：互动

### 5.1 页面定位

打开 App 默认进入的页面。按时间倒序展示双方互动，**左右分边、无头像**，不做聊天气泡。

- 她发来的在左（白卡），我发出去的在右（暖橘卡）
- 不是"只有今天"：默认加载 20 条，触底继续往回拿更早的
- 按天分组，换天插一条日期小标题（今天 / 10/19 / 10/18…）
- 顶部副标题：`今天 · 互相惦记了 N 次`，点一下补充浮现 `，相互戳了 M 次`

### 5.2 卡片类型

| 类型 | 方向 | 进互动流 | 完成数据 |
|---|---|---|---|
| 喝水 | 我 ⇄ TA | 是 | mL |
| 起身 | 我 ⇄ TA | 是 | 次数 |
| 提肛 | 我 ⇄ TA | 是 | 组数 |
| 惦记（自定义） | 我 ⇄ TA | 是 | 附言 ＋ 单图 |
| 戳一下 | 我 ⇄ TA | 是（细线，不是卡片） | 无 |
| 自己打卡 | 我 → 我 | 否，只进日常 | — |

### 5.3 卡片结构

```
她发来的（左，白卡）—— 卡面上没有任何状态文字
┌───────────────────────────────┐
│ 💧 喝水                  2 分钟前 │
│ 膀胱炎要记得喝水！               │
│ [ 回应 ]  [ 知道了 ]             │
└───────────────────────────────┘

我发出去的（右，暖橘卡）
未读 ┌───────────────────────────┐
     │ 💧 喝水            30 分钟前 │
     │ 多喝点温水                   │
     │                        ◢   │ ← 折角＝有回应内容
     └───────────────────────────┘

戳一下（唯一收成细线的一类）
──────────────────────────────────
👆 她   刚刚                        [ 回戳 ]
──────────────────────────────────
```

### 5.4 卡片字段

1. 类型图标 ＋ 类型名（喝水 / 起身 / 提肛 / 惦记）
2. 相对时间（刚刚 / 2 分钟前 / 16:30）
3. 正文（可选）
4. 状态标记（**只在卡片外侧**，规则见 5.5）
5. 待回应时增加「回应」（主）＋「知道了」（次，仅未读时出现）
6. 有回应内容时，右下折角

### 5.5 状态标记规则（核心）

**一句话：卡片里永远不写状态；她发来的什么都不标；我发出去的只在"当天、还没做"时标两个字。**

| 情况 | 卡片外侧 | 卡片内侧 | 点开详情 |
|---|---|---|---|
| 她发来 · 未读 | 无 | 无 | 状态胶囊「未读」 |
| 她发来 · 看过没做 | 无 | 无 | 状态胶囊「仅读」 |
| 她发来 · 已回应 | 无 | 无，只有折角 | 状态胶囊「已回应」 |
| 我发出 · 她还没看 | **未读**（主色加粗小字，与卡片底部对齐） | 无 | 状态胶囊「未读」 |
| 我发出 · 她看了没做 | **仅读**（灰色小字） | 无 | 状态胶囊「仅读」 |
| 我发出 · 已回应 | **不标**，只有折角 | 无 | 状态胶囊「已回应」 |
| 任何一条 · 跨天了 | **不标**（连未读/仅读都不标） | 无 | 仍可在详情里看到当时状态 |

约束：

- 「已回应」不写成文字，靠折角 ＋ 点开看回应内容确认
- 不用「看了，还没做」「还没看」「当天没做」这类长句
- 未读/仅读是**她读没读**，不是催办；不显示红点角标、不做红点轰炸

### 5.6 交互规则

- 点任何卡片 → 卡片详情弹层（互动与惦共用同一份）
- 「回应」→ 回应弹层：喝水给 ml 快捷、起身/提肛给次数、都可附一句 ＋ 单图
- 「知道了」只停提醒，不标记做没做（标记为仅读）
- 点开卡片即视为看过（她发的会从"未读"变"仅读"）
- 触底加载更早的 20 条，加载中有短提示
- 下拉刷新拉取最新
- 本地先展示，再与服务器校正

### 6.2 From 她

- 显示当天 TA 发给我的提醒，按时间倒序

- 行上不写任何状态文案；回应过的只留折角

- 当天她没发：`她今天还没惦记你哦` ＋ "等一会儿就好，或者你先开口"

- 显示当天我发给 TA 的提醒
- 不提供重复发送，只显示状态：行尾 **未读 / 仅读**，已回应不写
- 有回应内容的行带折角
- 底部常驻按钮「＋ 惦记 她」，空态里也有一个

### 6.4 历史

- 从右上角"历史 ›"进入
- 分组：今天 / 昨天（更早的随数据追加）
- 筛选：全部 / From 她 / To 她
- 跨天的条目**不写"当天没做"**，页脚只留一句：`当天没做的，就留在这里 / 不追、不罚、不算账`
- 历史只做记录，不再发送提醒

### 6.5 文案

| 区域 | 空态 | 有数据 |
|---|---|---|
| From 她 | 她今天还没惦记你哦 | 她今天惦记了你 {count} 次 |
| To 她 | 你今天还没惦记她呢 | 你今天惦记了 TA {count} 次 |
| 历史 | 当天没做的，就留在这里 | — |

## 七、提醒类型

### 7.1 五种类型

| 类型 | 内容规则 | 完成数据 | 图标 |
|---|---|---|---|
| 喝水 | 可选简短正文 ＋ 3 条建议句 | 水量 ml | 💧 |
| 起身 | 可选简短正文 ＋ 3 条建议句 | 次数 | 🧍 |
| 提肛 | 可选简短正文 ＋ 3 条建议句 | 组数 | 🌿 |
| 惦记（自定义） | 仅标题，≤15 字 | 附言 ＋ 单图 | ✎ |
| 戳一下 | 无正文、不点开、不需回应 | 无 | 👆 |

发送弹层一行五个类型，选完即出对应输入区，只有一个「发送」。

### 7.2 自定义任务规则

- 标题最多 15 个 Unicode 字符
- 标题不得为空
- 不预设内容模板
- 完成只有"已完成"一种主状态
- 可附加一句简单回复
- 可附加一张图片
- MVP 不支持多图、视频、语音

### 7.3 单次即时规则

1. 每次发送生成一条独立提醒
2. 未回应不影响发送下一条
3. 不自动重复
4. 用户可再次手动发送
5. 服务器对同一动作做幂等处理

## 八、状态模型

### 8.1 界面只讲两件事

| 维度 | 取值 | 谁看得见 |
|---|---|---|
| 做没做 | `todo` 待做 / `done` 已回应 | 双方 |
| 读没读（仅她发来的/我发出去的未做条目） | `unread` 未读 / `read` 仅读 | 我发出去的才在卡外标字 |

- 「已回应」不显示为文字，用折角 ＋ 详情里的状态胶囊表达
- 跨天即离开"今天"，掉进历史，不再标任何状态
- "知道了"只把 `silenced` 置真 ＋ `read` 置真，不改 `state`

### 8.2 服务端内部状态（不进 UI）

| 状态 | 用途 |
|---|---|
| `pending` / `delivered` | 推送投递与补发，仅用于重试与排查 |
| `expired` | 跨天归档（对应"掉进历史"） |
| `cancelled` | 发送方在极短时间内撤回（MVP 不开放入口） |

### 8.3 合法流转

```
todo ──回应──> done
todo ──知道了──> todo(silenced, read)
todo ──跨天──> 归档（历史，只读）
```

不允许从 `done` 回到 `todo`。

### 8.4 "看到"的定义

只有以下动作才算 `read`：

1. 点击系统通知
2. 点击互动卡片（进详情）
3. 点击惦页的提醒行
4. 通知上的「知道了」也算看过

滑掉通知、锁屏显示、状态栏露出均不算已读。

## 九、Tab 3：日常

### 9.1 页面定位

日常页不是聊天记录，而是个人习惯模块。可增删、快速打卡，并查看今日进度与最近 7 天。

### 9.2 默认模块

| 模块 | 数据类型 | 快速打卡 |
|---|---|---|
| 喝水 | mL | +200 / +300 / +500 / 自定义 |
| 起身站立 | 次数 | 记一次 |
| 提肛 | 次数 | 记一次 |

模块可自行添加（名字 ≤8 字 ＋ 每天 1/2/3/5/8 次），可删除。

### 9.3 模块卡片

```
┌──────────────────────────────────────┐
│ 💧 喝水                  550/2000 ml │
│ 今天 2 次记录                         │
│ ██████░░░░░░░░░░░░░ 28%              │
│ [+200] [+300] [+500] [自定义]        │
│ 今天 · 15:30 +250ml · 14:00 +300ml  [趋势 ›] │
└──────────────────────────────────────┘

┌──────────────────────────────────────┐
│ 🧍 起身站立                  2/6 次   │
│ ██████░░░░░░░░░░░░░                  │
│ 今天 · 15:05 · 11:20          [趋势 ›] │
│ 还差 4 次                    [记一次] │
└──────────────────────────────────────┘
```

规则：

- **只有喝水记水量，其余模块只记次数**
- 满目标显示「已完成」，想继续也能接着打（显示"多做 N 次"），不封顶
- 每张卡片**只有一个历史入口：右上/行尾的「趋势 ›」**

### 9.4 趋势页（所有模块一致）

点任意模块的「趋势 ›」进同一张页，只是数据不同：

1. 近 7 天 / 近 30 天切换
2. 7 根柱子，今天在最右并高亮；虚线为目标
3. 日均 ＋ `N/7 天达标`
4. 最多的一天 / 最少的一天（值 ＋ 日期）
5. 「今天的每一条」：逐条时间与数值（喝水带 ml，次数带第几次）
6. 今日合计与目标
7. 趋势页只读，不发提醒

> 已废弃：单独的「记录」弹层。原来喝水卡上同时挂"记录"和"7 天趋势"两个入口，信息重复；现在每个模块只有一个「趋势 ›」。

### 9.5 与提醒的关系

- 收到喝水提醒并回应：选水量，同时写入日常
- 收到起身 / 提肛提醒并回应：记一次，同时写入日常
- 日常自己打卡：只写日常，不反向生成互动卡片
- 同一提醒多次完成必须幂等，不能重复计入

### 9.6 设置入口

Tab 3 右上角齿轮图标，包含：

- 每日目标设置（喝水 ml、起身次数、提肛次数）
- 账号信息（手机号、身份、绑定日期）
- 关于（版本、推送状态）
- 退出登录

### 13.2 系统架构

```
┌─────────────────┐         ┌─────────────────┐
│   老婆手机       │         │   老公手机       │
│  (小米设备)      │         │  (小米设备)      │
└────────┬────────┘         └────────┬────────┘
         │                           │
         │         HTTPS / WS        │
         └───────────┬───────────────┘
                     │
            ┌────────┴────────┐
            │  你的小服务器    │
            │  ─────────────  │
            │  Node.js + Exp  │
            │  ─────────────  │
            │  SQLite         │
            │  ─────────────  │
            │  本地磁盘图片   │
            │  Nginx 静态    │
            └────────┬────────┘
                     │
            ┌────────┴────────┐
            │   小米推送服务   │
            │  (仅小米设备)   │
            └─────────────────┘
```

### 13.3 推送策略

1. 主通道：小米推送（MiPush）
2. 在线加速：WebSocket
3. 上线补发：sync 接口
4. 离线队列：本地 outbox

不强依赖常驻 WebSocket。前台正常心跳，后台降低探测，失败后指数退避。

### 13.4 后台边界

- 不设计永久前台服务
- 不诱导关闭所有电池优化
- 不用隐藏 API 自启动
- 不绕过 Android 10 以后的后台 Activity 限制
- "知道了"后的下一次提醒由用户手动触发

## 十八、产品愿景

> **惦，把"我在乎你"变成一个动作。**

它不是一款功能繁多的 App，而是两个人之间的一根线——轻、细、不断。

你点一下，她就知道你在惦记她。
她点一下，你就知道她收到了。

没有已读不回，没有催办的红点，没有社交压力。
只有一句简单的：**回你了。**
